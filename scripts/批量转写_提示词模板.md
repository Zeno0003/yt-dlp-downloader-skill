# 批量转写 · 通用提示词模板

**用途**：在新对话里（零上下文）粘一段话，让它把指定几条视频转成文字并跑完。
新对话的 Agent 看不到我们这次聊的内容，所以下面每一段都写成**自带全部路径与要求**的独立指令。

---

## 一、标准版（推荐，直接复制，只改数字）

```
请加载 yt-dlp-downloader 技能，然后帮我把微博「老马自奋蹄 · 商业创新合集」的
视频转成文字。

【改这里 ↓ 决定跑哪几条，其余原样照抄】
    batch_pipeline.py --next 20        ← 从第一个还没转写的往后跑 20 条（最省心，推荐；单批别超 40）
    batch_pipeline.py 1-60            ← 按序号跑 1–60
    batch_pipeline.py 469-469         ← 只跑第 469 条

完整命令（务必用后台跑）：

/Users/zeno/.workbuddy/binaries/python/versions/3.13.12/bin/python3 \
  ~/.workbuddy/skills/yt-dlp-downloader/scripts/batch_pipeline.py --next 20

硬性要求：
1. 用 run_in_background 跑，不要前台跑（前台 120 秒会被杀，只留半截文件）
2. 只出 TXT，不生成 SRT。**视频 mp4 要保留，不要删**（脚本默认就保留）
3. 素材命名是 `<序号>_<标题>_<视频ID>`，每份 TXT 顶部要有表头（序号/标题/时长/链接）
   —— 脚本自己会做，不要另外改名或改内容
4. 新对话不要重新抓清单、不要改条目编号、不要动 data/ 下的清单文件
   （00_核对报告.md、商业创新合集_*.tsv/.md/urls.txt、.sync_state.json、.known_ids.txt）；
   data/转写进度.md 由脚本自己追加，属正常
5. 脚本是幂等的：已转过的自动跳过，重复跑安全；中断了用同样命令续跑即可
6. 开跑前先看一下还剩多少：batch_pipeline.py --status
7. 跑完向我报告：成功几条 / 跳过几条 / 失败哪几条（带标题）/ 热压峰值
8. **不要按时长过滤任何视频。** 合集里有 2 条不到 1 分钟的（#329 是 0:40、#352 是 0:10），
   它们是合集的正规成员，必须照转。判断某条该不该跑只看清单，不看时长。
9. 若某条视频下载报 404，**不要就此判定它失效** —— 脚本会自动按 540P → 720P → 1080P
   逐档重试（微博三档音轨相同，换档不影响转写）。三档都失败才算真没了；
   那时才考虑手工记进 data/.unavailable.txt（**别自动往里写**）。
10. **画质不要动。** 转写一律从最小档 540P 起步，只有它坏了才逐档上推 720→1080。
    微博三档的**音轨完全一样**（实测 AAC HE-AAC / 44.1kHz / 双声道 / 128kbps），
    且**没有纯音频流、也没有比 540P 更小的档** —— 所以**画质完全不影响转写出来的文字**。
    不要为转写去追求高画质，也不要试图"只下音频"（微博做不到）。

如果这一批跑完还想要一份「总的长文」，命令尾部加 --merge：

/Users/zeno/.workbuddy/binaries/python/versions/3.13.12/bin/python3 \
  ~/.workbuddy/skills/yt-dlp-downloader/scripts/batch_pipeline.py --next 20 --merge

如果担心机器烫，再加 --guard（热压到 serious 自动暂停，凉了继续）：

/Users/zeno/.workbuddy/binaries/python/versions/3.13.12/bin/python3 \
  ~/.workbuddy/skills/yt-dlp-downloader/scripts/batch_pipeline.py --next 20 --guard
```

## 三、常用替换表

把标准版第一段里的命令换成下面任何一条即可：

| 我想干的事 | 命令 |
|---|---|
| 跑序号 1–60 | `batch_pipeline.py 1-60` |
| 接着上次往后跑 40 条 | `batch_pipeline.py --next 40` |
| 只跑某几条（知道微博 id） | `batch_pipeline.py --ids 5084582845615713,5084945234006672` |
| 先看看会跑哪些，不实际跑 | `batch_pipeline.py 1-60 --dry-run` |
| 看还剩多少没转 | `batch_pipeline.py --status` |
| 跑完还要一份总长文 | 命令尾部加 `--merge` |
| 只补合并稿（不下载不转写） | `batch_pipeline.py 1-60 --merge-only` |
| 开自动冷却（防烫） | 命令尾部加 `--guard` |
| 更早开始冷却（fair 就歇） | 命令尾部加 `--guard --guard-at fair` |
| 视频已经下过了，只想转写 | 命令尾部加 `--skip-download` |
| 想省空间、转完删视频 | 命令尾部加 `--delete-video`（默认**保留**） |
| 清掉已转写的 mp4 | `batch_pipeline.py --cleanup`（幂等，可反复跑） |

> `--next N` 是最省心的："从第一个还没转写的开始跑 N 条"，不用记序号。
> **单批别超过 40 条**（删 mp4 有"单轮 50 个"的系统上限，见第六节；默认不删视频，所以平时碰不到）。

## 四、总的长文（合并稿）

单条 TXT 是按语音停顿切碎的，一行几个字，直接读很吃力。合并脚本会做四件事：
**剥掉表头**、拼回段落、按日期升序、套一张**术语纠错表**（SARS→SaaS、搓衣板→洗衣机板 之类）。

**最省事：跑批时直接加 `--merge`**（转写完自动合并）：

```
/Users/zeno/.workbuddy/binaries/python/versions/3.13.12/bin/python3 \
  ~/.workbuddy/skills/yt-dlp-downloader/scripts/batch_pipeline.py --next 20 --merge
```

**只补合并稿**（不下载不转写，已有 TXT 也能合并）：

```
/Users/zeno/.workbuddy/binaries/python/versions/3.13.12/bin/python3 \
  ~/.workbuddy/skills/yt-dlp-downloader/scripts/batch_pipeline.py 1-60 --merge-only
```

产出文件名自带范围，一眼知道是哪几条到哪几条：

```
/Users/zeno/WorkBuddy/yt-dlp视频转文本/商业创新合集_合并_序号1-60_20260911.md
```

一句话版提示词：

```
加载 yt-dlp-downloader 技能，跑 batch_pipeline.py 1-60 --merge-only，
把第 1 到 60 条合并成一份长文给我。
```

## 五、关于"电脑发烫"（2026-09-11 实测，结论和直觉不一样）

**先看实测**：一口气连转 **57 条 / 516 秒 GPU 满载**，热压峰值**只到 `fair(1)`，一次都没到 `serious`**，
自动冷却全程未触发（`cooled=0s`）。也就是说——**按 30 条一批跑，这台机器根本烫不起来。**

- ⚠️ **发热源是转写，不是下载。** 下载 60 条 / 1.1GB 那十几分钟里热压**一直 `nominal(0)`**。
  只有 mlx_whisper 转写阶段（GPU 满载，约 **26× 实时**）才会升温。
- 所以"分批"要按**音频总时长**切，不是按条数：`--status` 会直接告诉你待转音频合计多少小时。
  1 小时素材 ≈ 2.3 分钟 GPU 满载。
- 脚本**每转完一条都记录热压**（macOS 官方 `thermalState`：0 nominal / 1 fair / 2 serious / 3 critical），
  峰值写进 `transcript/_transcribe_report.json` 的 `peak_thermal`，台账写进 `data/转写进度.md`。
- 真被烫到过再考虑 `--guard`：到阈值就暂停、回落继续；`--guard-at fair` 更保守。
  本次校准证明**默认阈值 `serious` 是够安全的上限**，不必更严。
- **别在跑的时候把 Mac 放被子/枕头上**，进风口别堵。物理散热比任何软件手段都直接。

## 六、已知坑：单轮最多删 50 个文件

脚本转完会删 mp4，但**系统安全阀限制"一轮最多删 50 个文件"**。跑 `1-60` 这种大范围时，
删到第 50 个会被拦下并报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（脚本已容错：台账照写、不崩，但会剩下一批 mp4）。

- **对策一（推荐）**：单批 ≤ 40 条（`--next 40`），删除量天然在 50 以内。
- **对策二**：事后单独清，可反复跑，幂等：
  ```
  /Users/zeno/.workbuddy/binaries/python/versions/3.13.12/bin/python3 \
    ~/.workbuddy/skills/yt-dlp-downloader/scripts/batch_pipeline.py --cleanup
  ```
